Composer y Namespaces

Gestiona dependencias con Composer, organiza tu código con namespaces y usa PSR-4 autoloading.

1
Namespaces
Evitan conflictos de nombres entre clases y organizan el código en "carpetas lógicas".
src/Models/Usuario.php
<?php
// Declarar namespace — coincide con la ruta del archivo
namespace App\Models;

class Usuario {
    public function __construct(
        public readonly string $nombre,
        public readonly string $email
    ) {}
}
?>
src/Services/UsuarioService.php
<?php
namespace App\Services;

// Importar con use
use App\Models\Usuario;
use App\Models\Producto as Prod;  // alias

class UsuarioService {
    public function crear(string $nombre, string $email): Usuario {
        return new Usuario($nombre, $email);
    }
}
?>
index.php
<?php
// Cargar el autoloader de Composer (carga clases automáticamente)
require_once 'vendor/autoload.php';

use App\Services\UsuarioService;

$service = new UsuarioService();
$usuario = $service->crear("Ana", "ana@mail.com");
echo $usuario->nombre;  // Ana
?>
2
Composer — Gestor de dependencias
El estándar para instalar, actualizar y gestionar librerías PHP.
  1. Descarga e instala Composer desde getcomposer.org — queda disponible como comando global.
  2. En tu proyecto ejecuta composer init para crear el archivo composer.json.
  3. Instala paquetes con composer require nombre/paquete.
  4. Incluye vendor/autoload.php en tu proyecto para cargar todo automáticamente.
Terminal — comandos Composer
# Instalar paquete (guarda en composer.json)
composer require guzzlehttp/guzzle       # HTTP client popular
composer require vlucas/phpdotenv        # variables .env
composer require ramsey/uuid             # generador de UUIDs

# Solo en desarrollo
composer require --dev phpunit/phpunit   # framework de tests

# Actualizar todas las dependencias
composer update

# Regenerar autoloader (tras añadir clases propias)
composer dump-autoload

# Ver paquetes instalados
composer show
composer.json
{
    "name": "mi-empresa/mi-proyecto",
    "description": "Mi aplicación PHP",
    "require": {
        "php": "^8.1",
        "guzzlehttp/guzzle": "^7.0",

    },

        "psr-4": {
            "App\\": "src/"
        }
    }
}

Ejemplos reales con Composer
Usando Guzzle (HTTP client) y PHPDotenv (variables de entorno).
guzzle_ejemplo.php
<?php
require_once 'vendor/autoload.php';

use GuzzleHttp\Client;
use GuzzleHttp\Exception\RequestException;

$client = new Client(['base_uri' => 'https://api.github.com']);

try {
    $response = $client->get('/users/torvalds', [
        'headers' => ['User-Agent' => 'MiApp/1.0'],
    ]);

    $datos = json_decode($response->getBody(), true);
    echo "Nombre: {$datos['name']}\n";
    echo "Repos públicos: {$datos['public_repos']}\n";

} catch (RequestException $e) {
    echo "❌ Error: " . $e->getMessage();
}
?>

config.php
<?php
require_once 'vendor/autoload.php';

use Dotenv\Dotenv;

// Carga el archivo .env
$dotenv = Dotenv::createImmutable(__DIR__);
$dotenv->load();
$dotenv->required(['DB_HOST', 'DB_NAME', 'DB_USER']);

// Leer variables seguras
$config = [
    'db_host' => $_ENV['DB_HOST'],
    'db_name' => $_ENV['DB_NAME'],
    'db_user' => $_ENV['DB_USER'],
    'db_pass' => $_ENV['DB_PASS'],
];

// Usar en PDO
$pdo = new PDO(
    "mysql:host={$config['db_host']};dbname={$config['db_name']}",
    $config['db_user'],
    $config['db_pass']
);
?>
tests/CalculadoraTest.php
<?php
use PHPUnit\Framework\TestCase;

class Calculadora {
    public function sumar(int $a, int $b): int { return $a + $b; }
    public function dividir(float $a, float $b): float {
        if ($b == 0) throw new InvalidArgumentException("División por cero");
        return $a / $b;
    }
}

class CalculadoraTest extends TestCase {
    private Calculadora $calc;

    protected function setUp(): void {
        $this->calc = new Calculadora();
    }

    public function testSumar(): void {
        $this->assertEquals(5, $this->calc->sumar(2, 3));
    }

    public function testDividirPorCero(): void {
        $this->expectException(InvalidArgumentException::class);
        $this->calc->dividir(10, 0);
    }
}
?>

Estructura de Proyecto PHP Profesional
La organización recomendada para un proyecto PHP moderno.
Estructura de carpetas
mi-proyecto/
├── public/              # Único directorio público (DocumentRoot)
│   └── index.php        # Punto de entrada de la aplicación
├── src/                 # Código fuente (PSR-4: App\)
│   ├── Controllers/     # Lógica de petición HTTP
│   ├── Models/          # Entidades de datos
│   ├── Services/        # Lógica de negocio
│   └── Repositories/    # Acceso a BD
├── tests/               # Tests unitarios y de integración
├── config/              # Archivos de configuración
├── storage/             # Logs, caché, uploads
│   ├── logs/
│   └── uploads/
├── vendor/              # Dependencias de Composer (no tocar)
├── .env                 # Variables de entorno (NO al repo)
├── .env.example         # Plantilla del .env (sí al repo)
├── .gitignore           # Excluir vendor/, .env, etc.
└── composer.json        # Dependencias y configuración PSR-4
Configura Apache/Nginx para que el DocumentRoot apunte a public/. Así todo el código en src/ nunca será accesible directamente desde el navegador — mucho más seguro.
