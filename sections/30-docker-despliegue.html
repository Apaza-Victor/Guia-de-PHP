Docker y Despliegue

Containeriza tus aplicaciones PHP, configura CI/CD automatizado y despliega a produccion con confianza.

1
Que es Docker
Containers vs VMs, porque Docker para PHP, imagenes, contenedores, volumenes y redes.
Docker empaqueta tu aplicacion con todo lo que necesita (runtime, dependencias, configuracion) en un container portable que corre igual en cualquier maquina.
Containers vs Maquinas Virtuales
Docker Containers
  • ✓ Arranque en segundos
  • ✓ Peso ligero (MB)
  • ✓ Comparten kernel del host
  • ✓ Facil de versionar (Dockerfile)
  • ✓ Consumo minimo de recursos
Maquinas Virtuales
  • ✗ Minutos en arrancar
  • ✗ Peso pesado (GB)
  • ✗ OS completo por VM
  • ✗ Mas dificil de automatizar
  • ✗ Alto consumo de RAM/disco
Comparativa de entornos de desarrollo PHP
Caracteristica XAMPP Laragon Docker Produccion real
Portabilidad Solo Windows Solo Windows Cualquier OS Linux mayormente
Similitud con prod Baja Media Identica N/A
Facilidad uso Muy facil Muy facil Curva inicial Complejo
Versiones PHP Una por instalacion Cambia rapido Cualquier version Cualquier version
Servicios extra Limitado Bueno Redis, Mongo, etc. Todo
Docker usa el mismo kernel que el host OS. En Windows/Mac corre una VM Linux diminuta automaticamente via Docker Desktop.

Docker para PHP
Dockerfile con extensiones esenciales, docker-compose con PHP + Apache + MySQL, y comandos para construir y ejecutar.
Dockerfile
# Imagen base oficial de PHP con Apache
FROM php:8.3-apache

# Instalar extensiones PHP esenciales
RUN docker-php-ext-install pdo_mysql mbstring opcache bcmath gd
RUN a2enmod rewrite

# Instalar Composer desde imagen oficial
COPY --from=composer:latest /usr/bin/composer /usr/bin/composer

# Establecer Directorio de Trabajo
WORKDIR /var/www/html

# Copiar el codigo de la aplicacion
COPY . .

# Ajustar permisos
RUN chown -R www-data:www-data /var/www/html \
    && chmod -R 755 /var/www/html/storage

# Copiar configuracion de Apache virtual host
COPY docker/apache.conf /etc/apache2/sites-available/000-default.conf

# Puerto de la aplicacion
EXPOSE 80

# Comando de inicio
CMD ["apache2-foreground"]
docker-compose.yml
version: "3.9"

services:
  # Servicio PHP con Apache
  web:
    build: .
    ports:
      - "8080:80"
    volumes:
      - .:/var/www/html
    depends_on:
      - db
    environment:
      - DB_HOST=db
      - DB_NAME=mi_app
      - DB_USER=root
      - DB_PASS=secret

  # Servicio MySQL
  db:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=secret
      - MYSQL_DATABASE=mi_app
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
Terminal
# Construir y levantar todo en segundo plano
docker compose up -d --build

# Ver logs en tiempo real
docker compose logs -f web

# Entrar al container PHP
docker compose exec web bash

# Ejecutar composer install dentro del container
docker compose exec web composer install

# Ejecutar migraciones
docker compose exec web php artisan migrate

# Parar todo
docker compose down

# Parar y eliminar volumenes (cuidado: borra datos)
docker compose down -v

# Rebuild completo
docker compose up -d --build --force-recreate

Docker Compose Completo
Setup multi-servicio: PHP-FPM, Nginx, MySQL, Redis y phpMyAdmin con volumenes y redes dedicadas.
  1. Crea la carpeta del proyecto y el archivo docker-compose.yml.
  2. Crea la carpeta docker/ con los archivos de configuracion de Nginx y PHP.
  3. Ejecuta docker compose up -d y accede en http://localhost:8080.
docker-compose.yml — Produccion completa
version: "3.9"

services:

  # --- PHP-FPM (procesa el codigo PHP) ---
  php:
    build:
      context: .
      dockerfile: docker/Dockerfile.php
    volumes:
      - ./src:/var/www/html
    environment:
      - APP_ENV=production
      - DB_HOST=mysql
      - DB_PORT=3306
      - DB_NAME=mi_app
      - DB_USER=app_user
      - DB_PASS=${DB_PASSWORD}
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    networks:
      - backend

  # --- Nginx (servidor web reverse proxy) ---
  nginx:
    image: nginx:1.25-alpine
    ports:
      - "8080:80"
      - "8443:443"
    volumes:
      - ./src:/var/www/html
      - ./docker/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - php
    networks:
      - backend

  # --- MySQL 8 ---
  mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASS}
      - MYSQL_DATABASE=mi_app
      - MYSQL_USER=app_user
      - MYSQL_PASSWORD=${DB_PASSWORD}
    volumes:
      - mysql_data:/var/lib/mysql
      - ./docker/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - backend

  # --- Redis (cache y sesiones) ---
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    command: redis-server --requirepass ${REDIS_PASSWORD}
    volumes:
      - redis_data:/data
    networks:
      - backend

  # --- phpMyAdmin (admin web de MySQL) ---
  phpmyadmin:
    image: phpmyadmin:5
    ports:
      - "8081:80"
    environment:
      - PMA_HOST=mysql
      - PMA_PORT=3306
      - MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASS}
    depends_on:
      - mysql
    networks:
      - backend

volumes:
  mysql_data:
  redis_data:

networks:
  backend:
    driver: bridge
docker/nginx.conf
server {
    listen 80;
    server_name localhost;
    root /var/www/html/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass   php:9000;
        fastcgi_index  index.php;
        fastcgi_param  SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include        fastcgi_params;
    }
}

CI/CD con GitHub Actions
Pipeline automatico: testear, construir y desplegar tu app PHP al hacer push a main.
CI = Integracion Continua (testear automaticamente). CD = Despliegue Continuo (publicar automaticamente). GitHub Actions ejecuta workflows gratis para repos publicos.
  1. Crea la carpeta .github/workflows/ en la raiz de tu repositorio.
  2. Agrega el archivo deploy.yml con el pipeline completo.
  3. Configura los Secrets del repositorio (Settings > Secrets) para credenciales de produccion.
  4. Al hacer push a main, el workflow ejecuta tests, build y despliegue automatico.
.github/workflows/deploy.yml
name: CI/CD Pipeline

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

env:
  PHP_VERSION: "8.3"

jobs:

  # ── FASE 1: Tests ──
  test:
    name: PHPUnit Tests
    runs-on: ubuntu-latest

    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: root
          MYSQL_DATABASE: test_db
        ports:
          - 3306:3306
        options: --health-cmd="mysqladmin ping"

    steps:
      - uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ env.PHP_VERSION }}
          extensions: pdo_mysql, mbstring, xml
          coverage: xdebug

      - name: Install Dependencies
        run: composer install --no-progress

      - name: Copy .env
        run: cp .env.example .env

      - name: Run PHPUnit
        run: vendor/bin/phpunit --coverage-text

  # ── FASE 2: Build Docker ──
  build:
    name: Build Image
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'

    steps:
      - uses: actions/checkout@v4

      - name: Build Docker Image
        run: docker build -t mi-app:${{ github.sha }} .

      - name: Save Image
        run: docker save mi-app:${{ github.sha }} | gzip > image.tar.gz

      - uses: actions/upload-artifact@v4
        with:
          name: docker-image
          path: image.tar.gz

  # ── FASE 3: Deploy ──
  deploy:
    name: Deploy to Server
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'

    steps:
      - uses: actions/download-artifact@v4
        with:
          name: docker-image

      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /var/www/mi-app
            docker compose down
            docker load < image.tar.gz
            docker compose up -d
            docker compose exec php php artisan migrate --force
Los Secrets (SERVER_HOST, SSH_PRIVATE_KEY) se configuran en Settings > Secrets and variables > Actions. Nunca se imprimen en logs.

/etc/nginx/sites-available/midominio.conf
server {
    listen 443 ssl http2;
    server_name midominio.com;
    root /var/www/mi-app/public;

    # SSL — Certbot genera estos archivos
    ssl_certificate     /etc/letsencrypt/live/midominio.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/midominio.com/privkey.pem;

    index index.php;

    # Headers de seguridad
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header Strict-Transport-Security "max-age=31536000";

    # Rutas limpias
    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # Procesar PHP via PHP-FPM
    location ~ \.php$ {
        fastcgi_pass  unix:/var/run/php/php8.3-fpm.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include       fastcgi_params;
    }

    # Bloquear archivos sensibles
    location ~ /\.(ht|git|env) {
        deny all;
    }
}

# Redirect HTTP a HTTPS
server {
    listen 80;
    server_name midominio.com;
    return 301 https://$host$request_uri;
}

Docker vs Hosting Tradicional
Pros, contras, costo, escalabilidad y complejidad de cada enfoque.
Aspecto Docker Hosting Tradicional
Configuracion inicial Requiere aprender Dockerfile y Compose Panel cPanel/Plesk, instantaneo
Reproduciibilidad Identico en dev, test y prod "Funciona en mi maquina"
Escalabilidad Horizontal con Docker Swarm/K8s Vertical (mas RAM/CPU)
Costo mensual $5-20 (VPS + Docker) $3-30 (depende del plan)
Control total Root access completo Limitado al panel
Mantenimiento Actualizas imagenes manualmente El hosting gestiona el server
Velocidad despliegue 1 comando: docker compose up Subir archivos via FTP/SFTP
Complejidad Curva de aprendizaje media Baja para sitios simples
Usa Docker cuando...
  • ✓ Tu equipo trabaja en multiples OS
  • ✓ Necesitas entornos replicables
  • ✓ Usas microservicios
  • ✓ Quieres CI/CD consistente
  • ✓ La app crecera en complejidad
Usa Hosting tradicional cuando...
  • ✓ Es un sitio WordPress o estatico
  • ✓ No tienes experiencia con servidores
  • ✓ Presupuesto muy limitado
  • ✓ Necesitas soporte tecnico incluido
  • ✓ El proyecto no crecera mucho
Punto intermedio: usa Laravel Forge o Forge Road para desplegar en VPS sin tocar Docker. Te dan un panel sobre un VPS puro, con deploy automatico via Git.
