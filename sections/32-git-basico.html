Git Basico para PHP

Domina el control de versiones con Git: comandos esenciales, branches, remotos y flujos de trabajo para equipos PHP.

1
Que es Git
Sistema de control de versiones distribuido, el estandar absoluto en desarrollo de software.
Git registra cada cambio en tu codigo como un "snapshot" (commit), permitiendo viajar en el tiempo, comparar versiones y colaborar sin conflictos.
Conceptos clave
# Conceptos fundamentales de Git

Repositorio (repo)   → Carpeta controlada por Git (.git)
Commit               → Snapshot del proyecto en un punto del tiempo
Branch               → Linea de desarrollo paralela (aislada)
Merge                → Unir dos branches en una sola
Remote               → Repositorio en linea (GitHub, GitLab)
Staging Area         → Zona intermedia para preparar el commit
Working Directory    → Tus archivos editados en disco
Comparacion: Git vs SVN vs Sin control
Caracteristica        │  Git           │  SVN          │  Sin control
──────────────────────┼────────────────┼───────────────┼──────────────
Tipo                  │  Distribuido   │  Centralizado │  N/A
Velocidad             │  Muy rapida    │  Lenta (red)  │  Rapida
Commits offline       │  Si            │  No           │  N/A
Branching             │  Liviano       │  Costoso      │  N/A
Merge                 │  Automatico    │  Manual       │  N/A
Historial             │  Completo      │  Por revision │  N/A
Comunidad/Ecosistema │  Mas grande    │  Pequena      │  N/A
Uso en PHP moderno    │  Estandar      │  Obsoleto     │  Peligroso

Instalacion y Configuracion
Instala Git en tu sistema y configura tu entorno para empezar a trabajar.
  1. Windows: Descarga desde git-scm.com — ejecuta el instalador y acepta las opciones por defecto.
  2. Mac: Ejecuta brew install git o instala Xcode Command Line Tools.
  3. Linux (Debian/Ubuntu): Ejecuta sudo apt install git
  4. Verifica la instalacion con git --version.
Terminal — Verificar instalacion
# Verificar que Git esta instalado
git --version
# git version 2.44.0.windows.1

# Inicializar un repositorio en tu proyecto PHP
cd mi-proyecto-php
git init
# Initialized empty Git repository in C:/mi-proyecto-php/.git/

# Ver el estado actual
git status
# On branch master — No commits yet
Terminal — Configuracion global
# Configuracion obligatoria — identidad del autor
git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"

# Configuracion recomendada
git config --global core.editor "code --wait"     # VS Code como editor
git config --global init.defaultBranch "main"      # Rama principal: main
git config --global core.autocrlf true             # Windows: saltos de linea

# Configuracion de colores
git config --global color.ui auto

# Alias utiles
git config --global alias.st "status"
git config --global alias.co "checkout"
git config --global alias.br "branch"
git config --global alias.cm "commit -m"
git config --global alias.lg "log --oneline --graph --all"

# Ver toda la configuracion
git config --list

Comandos Basicos
Los comandos que usaras todos los dias: agregar, commitear, ver historial y diferencias.
Terminal — Flujo basico de trabajo
# 1. Ver que archivos han cambiado
git status
# modified:   src/Controllers/AuthController.php
# new file:   src/Models/Producto.php
# deleted:    src/Legacy/OldHelper.php

# 2. Agregar archivos al staging
git add src/Models/Producto.php            # un archivo
git add src/Controllers/                  # carpeta entera
git add -A                                # todo (archivos nuevos + modificados)
git add -p                                # interactiva: elegir partes del archivo

# 3. Commitear con mensaje descriptivo
git commit -m "feat: agregar modelo Producto con validacion"

# 4. Ver el historial de commits
git log --oneline -5
# a1b2c3d feat: agregar modelo Producto
# f4e5d6c fix: corregir login redirect
# 9a8b7c6 chore: actualizar dependencias
# d3e2f1a docs: agregar README
# b0c1d2e feat: sistema de autenticacion
Terminal — Explorar historial y diferencias
# Ver historial detallado
git log
git log --oneline --graph --all    # grafico compacto
git log --author="Ana"             # commits de un autor
git log --since="2 days ago"       # ultimos 2 dias
git log -p src/Controllers/        # cambios en una carpeta

# Comparar archivos (working vs staging)
git diff                             # todos los cambios sin agregar
git diff --staged                    # cambios ya en staging
git diff main..feature-auth          # diferencia entre ramas
git diff a1b2c3d f4e5d6c            # entre dos commits

# Ver un commit especifico
git show a1b2c3d                     # ver commit completo
git show a1b2c3d:src/Models/Producto.php  # archivo en ese commit

# Ver historial de un archivo
git log --follow src/Models/Producto.php
Usa git log --oneline --graph --all como alias: git config --global alias.lg "log --oneline --graph --all". Ahora solo escribe git lg.
Terminal — Stash: guardar cambios temporalmente
# Guardar cambios sin commitear (comoDraft)
git stash
# Saved working directory index state:
# WIP on main: a1b2c3d feat: agregar modelo

# Ver lista de stash
git stash list
# stash@{0}: WIP on main: a1b2c3d
# stash@{1}: On feature: fix temporal

# Recuperar el stash mas reciente
git stash pop

# Recuperar sin eliminar el stash
git stash apply stash@{0}

# Guardar con descripcion
git stash push -m "cambios pendientes en auth"

# Eliminar un stash
git stash drop stash@{0}

# Limpiar todos los stash
git stash clear
Stash no es un backup. Solo es para cambios temporales. Siempre haz commit antes de cambiar de branch.

Branches
Trabaja en paralelo sin afectar la rama principal: crear, cambiar y fusionar ramas.
Terminal — Comandos de branches
# Listar ramas
git branch                    # solo locales
git branch -a                 # locales + remotas
git branch -v                 # con ultimo commit

# Crear y cambiar a una nueva rama
git checkout -b feature/carrinho
# Switched to a new branch 'feature/carrinho'

# Equivalente con git switch (mas moderno)
git switch -c feature/carrinho

# Volver a main
git switch main

# Fusionar una rama en la actual
git switch main
git merge feature/carrinho

# Eliminar rama (ya fusionada)
git branch -d feature/carrinho

# Eliminar rama remota
git push origin --delete feature/carrinho
Flujo de branches (texto)
main        ───●─────────────●─────────────●───
                │             ↑             ↑
feature      ──●───●───●───┘             │
                                        │
hotfix        ──────────────────────────●───┘
Terminal — Resolver conflictos de merge
# Intentar fusionar — conflicto detectado
git merge feature/carrinho
# CONFLICT (content): Merge conflict in src/Controllers/Carrito.php
# Automatic merge failed; fix conflicts and then commit.

# Ver archivos con conflicto
git status
# both modified: src/Controllers/Carrito.php

# Abrir el archivo y buscar los conflictos:
<<<<<<< HEAD
$items = $this->obtenerItems();         <── tu version (main)
=======
$items = $this->carrito->getItems();    <── version de feature
>>>>>>> feature/carrinho

# Editar: dejar la version correcta, eliminar los marcadores
# Guardar y luego:
git add src/Controllers/Carrito.php
git commit -m "merge: resolver conflicto en CarritoController"

Trabajo con Remotos
Conecta tu repositorio local con GitHub, GitLab o cualquier servidor remoto.
Terminal — Clonar y primer push
# === CLONAR un repositorio existente ===
git clone https://github.com/usuario/mi-proyecto-php.git
# Cloning into 'mi-proyecto-php'...
cd mi-proyecto-php

# === Crear repo local y subir por primera vez ===
git init
git add -A
git commit -m "feat: initial commit"
git branch -M main

# Agregar remoto (reemplaza con tu URL)
git remote add origin https://github.com/tu-usuario/mi-proyecto-php.git

# Subir al remoto
git push -u origin main
# -u = tracking: la proxima vez solo git push

# === Sincronizar con el remoto ===
git pull origin main           # traer + fusionar cambios remotos
git fetch origin               # solo descargar (no fusiona)
git push                       # subir commits al remoto

# Ver remotos configurados
git remote -v
Terminal — Flujo con fork (GitHub/GitLab)
# 1. Hacer fork del repositorio original en GitHub

# 2. Clonar TU fork
git clone https://github.com/TU-USUARIO/proyecto.git
cd proyecto

# 3. Agregar el repositorio original como "upstream"
git remote add upstream https://github.com/original/proyecto.git

# 4. Crear feature branch
git checkout -b feature/nuevo-metodo

# 5. Hacer cambios y commitear
git add -A
git commit -m "feat: implementar nuevo metodo de pago"

# 6. Subir a tu fork
git push origin feature/nuevo-metodo

# 7. Crear Pull Request desde GitHub

# 8. Mantener tu fork actualizado
git fetch upstream
git checkout main
git merge upstream/main
git push origin main

Gitflow y Convenciones
Estrategias de branching y convenciones de commits para equipos profesionales.
Gitflow — Estrategia de ramas
main (produccion)    ●─────────●─────────────●─────────●───
                       │         ↑             ↑         ↑
develop (integracion) ●───●─────●─────●───────●─────────────
                       │   ↑     ↑             ↑
feature/              └───┘     │             │
                                │             │
release/                       └───●─────┘   │
                                        │
hotfix/                                 └───●─────┘
Gitflow en accion — Ejemplo real
# === FLUJO COMPLETO ===

# 1. Nueva funcionalidad
git checkout develop
git checkout -b feature/sistema-pagos
# ... desarrollar, commitear ...
git checkout develop
git merge --no-ff feature/sistema-pagos
git push origin develop

# 2. Preparar release
git checkout develop
git checkout -b release/1.2.0
# ... fixes finales, actualizar version ...
git checkout main
git merge --no-ff release/1.2.0
git tag -a v1.2.0 -m "Release 1.2.0: sistema de pagos"
git checkout develop
git merge --no-ff release/1.2.0
git push origin main --tags

# 3. Hotfix (bug critico en produccion)
git checkout main
git checkout -b hotfix/fix-login-crash
# ... corregir bug ...
git checkout main
git merge --no-ff hotfix/fix-login-crash
git tag -a v1.2.1 -m "Hotfix: corregir crash en login"
git checkout develop
git merge --no-ff hotfix/fix-login-crash
Conventional Commits — Formato estandar
# Formato: tipo(alcance): descripcion

feat(auth): agregar autenticacion JWT para API
feat(carrinho): implementar carrito de compras
fix(pagos): corregir calculo de IVA en checkout
fix(892): resolver error 500 al subir imagen
chore: actualizar dependencias de Composer
chore(ci): configurar GitHub Actions para tests
docs: agregar guia de instalacion
docs(api): documentar endpoint /usuarios
refactor(models): extraer logica a ProductoService
test(auth): agregar tests para LoginController
style: aplicar PSR-12 al codigo fuente
perf(db): optimizar query de busqueda
ci: configurar pipeline de despliegue
build: agregar webpack para assets
