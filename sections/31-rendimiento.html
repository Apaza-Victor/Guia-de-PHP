Medir Rendimiento
No se puede optimizar lo que no se mide. Herramientas para medir tiempo y memoria.
medir_rendimiento.php
<?php
// Medir tiempo de ejecucion con microtime
$inicio = microtime(true);

// Simular trabajo pesado
$datos = range(1, 1000000);
$filtrados = array_filter($datos, fn($n) => $n % 2 == 0);
$suma = array_sum($filtrados);

$fin = microtime(true);
$memoria = memory_get_usage(true);
$memoria_peak = memory_get_peak_usage(true);

echo "Tiempo: " . round(($fin - $inicio) * 1000, 2) . " ms\n";
echo "Memoria actual: " . round($memoria / 1024) . " KB\n";
echo "Memoria pico: " . round($memoria_peak / 1024) . " KB\n";
?>
Usa microtime(true) en lugar de microtime() para obtener el valor como float, mas preciso para mediciones.

OPcache
Almacena bytecode precompilado en memoria para evitar leer y parsear archivos en cada peticion.
OPcache viene habilitado por defecto en PHP 8+. Verifica con php -m | findstr opcache o phpinfo().
php.ini — Configuracion recomendada de OPcache
; ====== OPCache Configuracion de Produccion ======

; Activar OPcache (1=on, 0=off)
opcache.enable=1

; Memoria compartida para el bytecode (en MB)
opcache.memory_consumption=128

; Memoria para strings internas (en MB)
opcache.interned_strings_buffer=16

; Maximo numero de archivos acelerados
opcache.max_accelerated_files=10000

; Revalidar caducidad en segundos (0 = cada request en dev)
opcache.revalidate_freq=0

; Habilitar validacion rapida de cambios en archivos
opcache.validate_timestamps=1

; Compilar scripts en segundo plano al iniciar
opcache.enable_cli=0


opcache.preload=/var/www/app/preload.php
Verificar estado de OPcache
<?php
// Ver info basica de OPcache
$status = opcache_get_status();

echo "Memoria usada: " . $status['memory_usage']['used_memory'] . " bytes\n";
echo "Scripts acelerados: " . $status['opcache_statistics']['num_cached_scripts'] . "\n";
echo "Hits: " . $status['opcache_statistics']['opcache_hit_rate'] . "%\n";

// Invalidar cache completa (desploys)
opcache_reset();

// Invalidar un archivo especifico
opcache_invalidate('/var/www/app/src/Config/routes.php');
?>
En desarrollo, desactiva OPcache o configura opcache.revalidate_freq=0 para ver cambios inmediatamente sin reiniciar PHP-FPM.
3
Estrategias de Caching
Almacena resultados costosos para reutilizarlos. Archivos, APCu, Redis y Memcached.
cache_archivo.php
<?php
function cache_get(string $key, int $ttl = 3600): ?array {
    $file = "cache/{$key}.cache";
    if (file_exists($file) && time() - filemtime($file) < $ttl) {
        return unserialize(file_get_contents($file));
    }
    return null;
}

function cache_set(string $key, mixed $data): void {
    file_put_contents("cache/{$key}.cache", serialize($data));
}

// Uso
$productos = cache_get('productos_top', 1800);
if ($productos === null) {
    $productos = obtenerProductosTop();  // consulta BD
    cache_set('productos_top', $productos);
}
?>
cache_apcu.php
<?php
// APCu: almacenamiento en memoria compartido del servidor
// Requiere extension: pecl install apcu

// Guardar en cache (clave, valor, TTL en segundos)
apcu_store('usuario:42', [
    'nombre' => 'Carlos',
    'email'  => 'carlos@mail.com'
], 3600);

// Obtener del cache (devuelve false si no existe)
$usuario = apcu_fetch('usuario:42', $found);
if (!$found) {
    $usuario = buscarUsuario(42);
    apcu_store('usuario:42', $usuario, 3600);
}

// Eliminar una clave
apcu_delete('usuario:42');

// Limpiar todo el cache APCu
apcu_clear_cache();
?>
cache_redis.php — con PhpRedis
<?php
// Extension PhpRedis (pecl install redis)
$redis = new Redis();
$redis->connect('127.0.0.1', 6379);

// Guardar con TTL (segundos)
$redis->setex('productos:top', 1800, json_encode($productos));

// Obtener
$data = $redis->get('productos:top');
if ($data) {
    $productos = json_decode($data, true);
} else {
    $productos = obtenerProductosTop();
    $redis->setex('productos:top', 1800, json_encode($productos));
}

// Eliminar clave
$redis->del('productos:top');
?>

Optimizacion de Base de Datos
Indices, EXPLAIN, consultas eficientes y conexion pooling para queries rapidas.
Antes vs Despues — Consulta optimizada
-- MAL: SELECT * sin indice, sin filtro, sin limite
SELECT * FROM productos WHERE nombre LIKE '%laptop%';

-- EXPLAIN muestra: ALL (scan completo de 50k filas)
-- type: ALL | key: NULL | rows: 50000

-- BIEN: solo columnas necesarias, indice, filtro optimo
SELECT id, nombre, precio
FROM productos
WHERE nombre LIKE 'laptop%'
LIMIT 20;

-- Crear indice para búsquedas por nombre
CREATE INDEX idx_productos_nombre ON productos(nombre);

-- Composite index para filtros frecuentes
CREATE INDEX idx_productos_cat_precio
    ON productos(categoria_id, precio);

-- EXPLAIN muestra: ref (busqueda por indice)
-- type: ref | key: idx_productos_cat_precio | rows: 20
conexion_pdo.php — Connection pooling
<?php
// Singleton PDO con persistent connections
class Database {
    private static ?PDO $instance = null;

    public static function getConnection(): PDO {
        if (self::$instance === null) {
            self::$instance = new PDO(
                'mysql:host=localhost;dbname=tienda;charset=utf8mb4',
                'root',
                'pass',
                [
                    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
                    PDO::ATTR_PERSISTENT         => true,   // reuse connection
                    PDO::ATTR_EMULATE_PREPARES  => false,  // prepared nativos
                ]
            );
        }
        return self::$instance;
    }
}

// Uso con prepared statements
$pdo = Database::getConnection();
$stmt = $pdo->prepare('SELECT id, nombre FROM usuarios WHERE email = ?');
$stmt->execute([$email]);
$usuario = $stmt->fetch(PDO::FETCH_ASSOC);
?>
Usa EXPLAIN SELECT ... antes de cada consulta en desarrollo. Busca que type no sea ALL y que key no sea NULL.

Lazy Loading y Optimizacion de Codigo
Carga diferida de clases, evitar N+1 y micro-optimizaciones PHP.
Problema N+1 — Antes vs Despues
<?php
// MAL: N+1 — 1 query para pedidos + N queries para usuario
$pedidos = $pdo->query('SELECT * FROM pedidos LIMIT 50')->fetchAll();
foreach ($pedidos as $pedido) {
    $stmt = $pdo->prepare('SELECT nombre FROM usuarios WHERE id = ?');
    $stmt->execute([$pedido['usuario_id']]);
    echo $stmt->fetchColumn();  // 51 queries totales!
}

// BIEN: JOIN resuelve todo en 1 sola query
$pedidos = $pdo->query('
    SELECT p.id, p.total, u.nombre
    FROM pedidos p
    JOIN usuarios u ON u.id = p.usuario_id
    LIMIT 50
')->fetchAll();

// 1 sola query — 50x mas rapido
foreach ($pedidos as $p) {
    echo "{$p['nombre']} — $\{$p['total']}\n";
}
?>
Lazy Loading de clases
<?php
// MAL: incluir todo al inicio
require_once 'lib/Logger.php';
require_once 'lib/ReportGenerator.php';
require_once 'lib/EmailSender.php';
require_once 'lib/PdfExporter.php';
// Todas las clases se cargan aunque no se usen

// BIEN: lazy load solo cuando se necesitan
function getLogger(): Logger {
    static $logger = null;
    if ($logger === null) {
        require_once 'lib/Logger.php';
        $logger = new Logger();
    }
    return $logger;
}
?>
Micro-optimizaciones PHP
<?php
// Evitar string concatenation en loops — usar array
// LENTO:
$html = '';
foreach ($items as $item) {
    $html .= "<li>{$item}</li>";
}

// RAPIDO:
$parts = [];
foreach ($items as $item) {
    $parts[] = "<li>{$item}</li>";
}
$html = implode('', $parts);

// isset() vs array_key_exists()
// isset es mas rapido (no verifica null como valor)
if (isset($array['clave'])) { }     // preferido
if (array_key_exists('clave', $array)) { }  // solo si el valor puede ser null

// Early returns — evita else innecesario
// MAL:
function procesar($dato): string {
    if (is_null($dato)) {
        return 'vacio';
    } else {
        return $dato->toString();
    }
}

// BIEN:
function procesar($dato): string {
    if (is_null($dato)) return 'vacio';
    return $dato->toString();
}
?>

Checklist de Produccion
Verifica cada punto antes de desplegar tu aplicacion PHP en servidor real.
Produccion PHP Checklist
OPcache activado (opcache.enable=1, memory=128MB+)
display_errors = Off, log_errors = On
error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT
Compresion GZIP/Brotli habilitada (Apache o Nginx)
CDN configurado para assets estaticos (CSS, JS, imagenes)
Minificacion de CSS y JS activada
Headers de cache HTTP configurados (Cache-Control, ETag)
Indices de BD creados para todas las columnas en WHERE y JOIN
Capa de cache implementada (Redis/APCu) para queries frecuentes
PHP actualizado a la version LTS mas reciente (8.2+)
Extensiones innecesarias deshabilitadas (ej. xdebug)
session.gc_maxlifetime ajustado segun necesidad
connection persistentes activados en PDO (ATTR_PERSISTENT)
HTTP/2 o HTTP/3 habilitado en el servidor web
SSL/TLS configurado con certificados actualizados
rate limiting activado para endpoints publicos
Logs estructurados (JSON) para monitoreo
Profiling periódico con Blackfire o Xdebug en staging
